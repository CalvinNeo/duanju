## 两层 prompt:关键帧 + 视频

EP01 走的是**首帧驱动(I2V)**:先生成关键帧,再拿关键帧当首帧生成视频。两层 prompt 结构完全不同,不要混用。

### 第一层:关键帧(`_build/kf_plan.json`,21 条)

外观、场景、座位、构图全部在这一层定死。段落结构:

| 段落 | 内容 | 覆盖 |
|---|---|---|
| 【朝向规则】 | 参考图角度 ↔ 画面朝向的绑定 | 21/21 |
| 【参考图】 | 图N = 场景底板 / 角色定妆照 / 道具定妆照 | 21/21 |
| 【场景图用法】 | 底板只定房间与机位,底板里的人不是本片角色 | 18/21 |
| 【房间】【墙面与方格】【光源】 | 逐字写死 | 21/21 |
| 【前情状态】 | 当前时刻的道具与生死 | 21/21 |
| 【画面内容】 | 本镜拍什么(已剥掉景别与运镜句) | 21/21 |
| 取景段 | 按镜头类型分支:【本镜取景】【纵深分层】【座钟 — 全片统一规格】【桌角旁必须有人】【死者朝向】等 | 按需 |

关键帧**不写**【运镜】【台词】【音效】【配乐】,改为加一句「这是一张静态剧照,画面中的人物保持静止,不说话」(21/21)。

提交参数(`sub_keyframe.py`):

```json
{
  "prompt": "...",
  "reference_images": [{"url": "<upload_temp_url 得到的 temp_url>", "mime_type": "image/jpeg"}],
  "aspect_ratio": "9:16",
  "area": "2K",
  "output_format": "png",
  "n": 1
}
```

参考图上限 **9 张**,装配顺序:场景底板 → 角色定妆照 → 山羊头骨 → 座钟视角定妆照。

> **每批最多 2 张。** `sub_keyframe.py` 的 BATCH=5 会触发 `UND_ERR_SOCKET`,拆成每批 ≤2 张稳定成功。

**首帧模式下不传 `ratio`** —— H3 会自动 adaptive,指定了反而报错;`reference_type` 传 `"first_frame"`。


## 提示词设计说明

这套提示词是按 H3 的实际脾气写的,不是通用模板:

- **一个镜头只做一个明确动作**,全部写成「单个连续长镜头,一镜到底」。
- **不写否定式约束**(不要/禁止/不能)。H3 对否定词不敏感甚至会反向理解,所有约束都改写成正面描述。
- **不使用减速词**(缓慢/缓缓/慢慢/轻轻)。这类词会把整段拖成慢动作,动作一律按真实世界实时速度写。
- **台词直接写进提示词**。H3 自带原生同步音轨,台词、环境音、音效、配乐都会一起生成,不需要另外配音。
- **外观靠参考图锁,不靠文字锚**。关键帧挂场景底板 + 角色三视图 + 道具定妆照(上限 9 张),再配【朝向规则】把参考图角度绑到画面朝向上;视频层则由【首帧锁定】继承。早期版本靠【人物】段写文字锚,实测压不住 —— 同一角色在 144 个独立任务里一定会漂。
- **场景里的关键标记必须每镜清晰可见**。本剧是墙面方格线(后段推理的伏笔),具体规格见 `分镜总表.md`「一、场景」。

## 人物朝向规范（强制要求）

> **不要用文字要求「背对镜头」—— 模型做不到。改为给模型背面与侧面的参考图。**

### 实测结论：文字约束无效

实测事故:KF_S003 里前景两人背对镜头,脖子却扭转 180 度回看镜头;KF_S001、KF_S013 里要求「背对镜头、只露后脑勺」的角色全部转成了正面。

根因:每个角色只挂了**正面定妆照**作为参考图。模型既想遵守座位安排,又想展示参考图里的脸,于是把头拧过来。**光靠文字写「不要扭头」是拦不住的。**

### 正确做法:三视图参考图

每个角色准备三个角度的定妆照,生成关键帧时按该人物在画面里的朝向**挂对应角度的参考图**:

| 人物在画面里的朝向 | 挂哪张参考图 |
|---|---|
| 面向镜头 | 正面定妆照 |
| 侧对镜头 | 侧面定妆照 |
| 背对镜头 | 背面定妆照 |

背面图的生成要求:「完全背对镜头,只看到后背、后脑勺与肩膀,完全看不到脸,头部保持朝前,不要回头」。侧面图:「正侧面,看到完整侧脸轮廓、耳朵与肩膀」。两张都用正面定妆照当参考图,确保是同一个人。

### 配套的文字约束（有了参考图之后才有效）

1. 每条提示词包含【朝向规则】段:「背对镜头的人必须完全背对镜头,只露出后背与后脑勺,看不到脸,绝对不允许扭头回看镜头,不允许出现脖子扭转的画面。面向镜头的人才露出脸。」
2. **背对镜头的人,在取景段里只用服装和发型描述,不给面部特征** —— 写「穿夹克、黑色短发的男人的后背与后脑勺」这类,不要写他的五官。
3. 同一画面里朝向必须符合几何:镜头这一侧的人必然背对镜头,对侧的人必然面向镜头,两侧的人是侧面。不允许所有人同时看镜头。具体座位与朝向对应见 `分镜总表.md`「二、座位表」。

## 关键帧规范（强制要求）

> **提示词自包含规范、取景与背景推算对关键帧同样有效。** 场景尺寸、座位表、座钟规格、机位与入画人数这些剧情约束,见 `分镜总表.md`「全片统一设定」。

关键帧是该镜头的第一帧,后续用首帧驱动视频。关键帧错了,视频一定错。

### 关键帧与视频提示词的差异

关键帧是**静态图**,因此:

- 去掉【运镜】【台词】【音效】【配乐】四段
- 增加一句「这是一张静态剧照,画面中的人物保持静止,不说话」
- **【房间】【墙面与方格】【光源】【前情状态】四段逐字保留**(21/21);取景段按机位分支生成;【唯一性】只在群像/越肩镜头出现(4/21)
- **空座类硬约束与入镜人数按机位分工**,具体清单见 `分镜总表.md`「四、机位、底板与入画人数」。原则只有一条:**人数由机位几何投影决定,不由景别查表**

## 说话人规范（强制要求）

> **落地状态:三层全部落地。** 分镜总表.md 9/9 镜有【说话人】段(`add_speaker.py`);21 张关键帧 prompt 9/9 有(`gen_keyframe.py`);21 条视频 prompt 9/9 有(`gen_ep01_video.py`)。规格与说话人清单共用 `_build/speaker_ep01.py`。

实测事故:S004 台词是「人羊开口说:早安,九位」,成片里却是一个藏青西装男在说话,人羊站在他身后。原因是取景段写了「画面正前方:章晨泽」,模型就把镜头和口型给了她;而章晨泽当时没有挂参考图,模型还把她编成了男人。

### 三条铁律在 prompt 里的落点

- **关键帧**:插在【参考图】之后、【房间】之前;有说话人的镜头开头静态句不能写「不说话」,否则与口型约束打架
- **视频**:插在【首帧锁定】之后、【镜头规则】之前
- 人羊戴全罩式头骨面具,没有可见的嘴,单独一套写法(不提口型)
- 代词按性别走

### 三条铁律

1. **单独写【说话人】段,放在参考图之后、其余所有段落之前。** 写明说话人的姓名+外形+位置,并补三句:「画面中只有他的嘴在动」「其他所有人的嘴全程紧闭,不做任何口型,不出声」「镜头正对他,他是画面的绝对主体」。
2. **取景段里必须把说话人标成画面主体**,写成「画面主体(本镜说话人):XXX」。其他入画的人后面一律加「(不说话,嘴紧闭)」。
3. **取景段里出现的每一个人,都必须同时挂上参考图。** 如果取景段写了「画面正前方:章晨泽」,就必须把章晨泽的定妆照加进 reference_images。否则模型会凭空编一个角色出来。

## 提示词自包含规范（强制要求,最高优先级）

> **每个镜头都是一次完全独立的生成。H3 不记得上一个镜头拍了什么。**
> **因此每一条提示词都必须自带完整的场景、全场人物、前情状态,不得依赖上下文。**

### 为什么这是硬要求

实测事故:EP01 成片里出现「6点钟方向的人从男变成女」「后面的镜头里只剩两个人」。
根因是早期版本为了防止 H3 多画人,在单人镜头里写了「画面中只有1个人」。
H3 照做,房间就空了;而没写全场人物表的镜头,H3 根本不知道每个座位该坐谁,于是随机分配甚至改性别。

### 关键帧必须包含的段落（21/21 实测覆盖）

| 段落 | 内容 | 缺了会怎样 |
|---|---|---|
| 1. 【朝向规则】 | 参考图角度 ↔ 画面朝向的绑定 | 背对镜头的人扭头回看镜头 |
| 2. 【参考图】 | 图N = 场景底板 / 角色定妆照 / 道具定妆照 | 人物长相漂移 |
| 3. 【场景图用法】 | 底板只定房间与机位,底板里的人不是本片角色 | 照抄底板里的占位剪影 |
| 4. 【房间】【墙面与方格】【光源】 | 房间尺寸、方格线、圆桌、座钟、钨丝灯、封闭性 | 房间变形、长出窗户 |
| 5. 【前情状态】 | 当前时刻的道具与生死（本剧清单见分镜总表第五节） | 道具凭空出现或消失 |
| 6. 【画面内容】 | 本镜拍什么（已剥掉景别与运镜句） | 与取景段打架 |
| 7. 取景段 | 按机位分支:【本镜取景】【纵深分层】【座钟 — 全片统一规格】【桌角旁必须有人】【死者朝向】【人数核对】… | 人数不对、桌角旁没人 |
| 8. 静态剧照句 | 「画面中的人物保持静止,不说话」 | 关键帧出现动态模糊 |

### 视频必须包含的段落（21/21 实测覆盖）

【首帧锁定】【镜头规则】【本镜动作】【运镜】【速度】【音效】六段固定,台词按需（9 镜有）。

> **「全场人物 11 人全部列出」这条没有实现。** 21 张关键帧里【全场人物】段 **0 次**、「房间里一共」句式 **0 次**。
>
> 实际存在的是**计数式**人数声明,共 5 处:群像 4 镜的【人数核对】「画面里一共正好 11 个人:前景背对镜头的 1 个 + 圆桌对面 9 个 + 站在桌外的人羊 1 个」,以及 S020 的「画面里一共 11 个人:10 个坐着的加 1 个站着的人羊」。
>
> 差别在于:**计数式只给总数,不给「谁坐几点」**。谁坐哪、穿什么、朝哪边,全部由**底板 + 角色三视图 + 取景段按机位分支**决定。所以人数靠几何投影算、身份靠参考图锁,不是靠逐字名单。

### 三条铁律

1. **禁止写「画面中只有N个人」。** 这条仍然有效,实测事故见上。现状的规避方式是**不写人数声明,改为用底板和取景段把该出现的人画出来**,并在越肩/群像镜头追加【人数核对】【桌角旁必须有人】【最左与最右两人】这类硬约束。
2. **人数靠几何算,不靠列名单。** 「全场人物 11 人全部列出」**没有实现**（0/21）。座位方位用时钟表示,全片固定不变,权威来源是 `_build/seat_geo.py` 的 `SEATS`;入画人数由 `screen_x_f` / `in_view` / `pick_shoulder_cam` 按机位投影算出来。
3. **前情状态必须写清当前时刻的道具与生死**（21/21 覆盖）。具体到本剧的道具状态推进表,见 `分镜总表.md`「五、道具状态」。

## 运镜规范（硬性要求）

> **核心原则:默认固定机位。能不动就不动,必须动的时候只动一次。**

观众实测反馈:运镜转来转去看晕了。整改前 143 个镜头里 93 个带运动(65%),其中 7 个用了弧线/环绕。
**整改后(母数据 144 镜实测):固定机位 125 个(86.8%),有运动 19 个(13.2%),弧线/环绕/旋转 0 个。**

### 硬性规则

1. **默认固定机位**。全片至少 **70%** 的镜头必须是固定机位(镜头位置与朝向全程不变),只靠演员走位和景别选择叙事。
2. **一个镜头最多一个运动指令**。禁止「先横移再摇回」这类复合运镜。
3. **禁止弧线移动、环绕、旋转**。这三类在竖屏窄画幅里最容易引起眩晕,**全片禁用**。
4. **禁止快速平移 / 快速横移**。需要扫过多人时,改用固定机位 + 演员依次转头,或拆成多个固定镜头。
5. **允许的运动只有三种,且幅度必须小**:轻微推进(不超过一个景别)、轻微拉远(不超过一个景别)、固定机位下的轻微手持晃动。
6. **运镜必须写明起止**。例如「镜头从中景轻微推进到中近景后停住」,不要写「镜头推进并环绕」。
7. **单集运动镜头不超过 30%**,且不要连续两个镜头都动。
8. **运镜只能写在【运镜】段,【本镜动作】段里不许出现任何运镜词。**
   两段同时写运镜就是自相矛盾,I2V 模型不会报错,会自己挑一种执行。

### 铁律 8 的实测依据（S017,2026-11-12）

S017 的动作段写了「撞击发生的瞬间**镜头剧烈晃动并向上甩开**」,运镜段却写「固定机位,镜头位置与朝向全程不变」。
模型没有晃动镜头,而是**把前景两个人整体向左平移了约 10% 画幅(≈75 px)**:墙、圆桌、座钟、对面一圈人全部纹丝不动,
只有死者(浅灰卫衣)和齐夏(炭灰夹克)滑走了。观众看到的就是「死人以及他左边那个灰衣服男的位置不对」。

| | 齐夏 | 死者 |
|---|---|---|
| S015 尾帧(基准) | 0.27 | 0.68 |
| S017 首帧 | 0.26 | 0.66 |
| S017 中帧 | **0.155** | **0.575** |
| S017 尾帧 | **0.15** | **0.58** |

定位手法(可复用):**首帧/尾帧红绿叠合**——首帧放 R 通道、尾帧放 G 通道,静止的内容呈灰色,
位移的内容呈红绿错边。再配合「背景墙条 vs 前景人物条」的列剖面互相关,就能把「机位动」和「人被平移」区分开。
注意背景墙是周期方格,直接互相关会混叠到相邻格线上,必须同时看前景条。

修法:动作段删掉运镜词(撞击的冲击力交给音效和身体动作),运镜段补「取景框的四条边全程框住同一片范围」,
再在 `gen_ep01_video.py` 的 `EXTRA` 里加两条正面约束把前景两人的画面位置钉死。
返工后同一镜前景位移 2–4 px(0.003–0.005 画幅)。

`gen_ep01_video.py` 已加自检 B:扫描【本镜动作】段里的运镜指令(镜头+晃动/甩/推近/拉远/摇/平移…),
命中即报错。已反向验证:旧文本命中 `['甩']`,新文本为空。

10. **每块底板都必须挂房间 / 墙面参考图,墙的形状与明暗不许交给模型自由发挥。**

   2026-11-13 实测:三块底板的房间根本不是同一个房间,根因是参考图配置完全不同 ——
   `12y4` 挂了上一代场景图所以房间是对的;`12z` 只挂山羊头骨和座钟,方形房间被画成
   **六边形**(左右侧墙向外斜张);`12x` 的 `reference_images` 是**空数组**,方格没画成阵列、
   墙面偏浅、还画了 4 行(设定只有 3 行);`12v3` 只挂座钟定妆照,墙面亮度 120,而其余底板 37-61。

   已重做为 `12z2` / `12x2` / `12v3b`,共用两张场景资产:`12room_标准方形房间.jpg`(空房间,
   锁方形盒子 + 竖直墙角 + 4 列 3 行 1 米方格)与 `12wall_方格墙.jpg`(从它裁下来的纯方格墙,
   无墙角/无天花板/无地面/无桌子/无人物,**不携带机位信息**)。桌心低机位必须用裁切图:
   它的机位是「圆桌几何正中心、离桌面 12 厘米、光轴水平」,与房间参考图的 1.5 米平视差太远,
   挂整张会把机位带偏。

   **给关键帧追加墙面参考图压不住底板** —— `12v3` 实测追加后亮度 86,反而更亮,只能重建底板。
   房间描述统一由 `_build/room_std.py` 提供(四档形状 + 写死行列数 + `CORNERS` 墙角块,全正面描述),
   验收判据与实测数值见 `分镜总表.md`「每块底板都必须挂房间 / 墙面参考图」。

9. **人羊的位置转换一律靠切镜头,不演走位。** 前一镜他站在原位,后一镜他已经到位,中间过程不演。

   S015 原文写的是「迈开步子,皮鞋踩地,绕过圆桌,走到死者身后站定」。实测模型把人羊从 x 0.72
   一路往右带到 x 0.95(走出画面右边缘),尾帧又变成一个占画面右侧约 20% 的大头骨特写 ——
   位置、尺寸、朝向全错。

   镜头内位移在本模型上有三类实测故障:把人带出画面;把「走近景」演成新增一个近景人羊
   (S016 分身);跨镜头位置互相矛盾。切镜头把「位移」变成「两个静止构图之间的省略」,三类一起消失。

   | 镜头 | 人羊状态 | 转换靠什么完成 |
   |---|---|---|
   | S015 | 站在画面右侧原位,双脚并拢不动,面具转向死者 | 站直凝视,不动 |
   | S016 | 上半身俯倾,一条手臂从自己肩上斜向下伸出去按住死者后脑 | S015→S016 的硬切 = 「他到位了」 |
   | S017 | 前景俯身,双手从颈后掐住死者往下压 | S016→S017 的硬切 = 「他压下去了」 |

   代价是失去走位的紧张感。替代方案:凝视 + 座钟滴答声放大 + 鼓点渐强。S015 从「他走过去了」
   改成「他站在那儿盯着他」,悬念反而更足。

   自检 D 会扫【本镜动作】段的人羊走位词(迈开步子 / 迈步 / 迈出 / 绕过圆桌 / 走到 / 走近 /
   踩地 / 走向),命中即报错。「走向」带负向断言,放过「骨纹走向 / 纹路走向」这类纹路描述 ——
   这条是实测踩出来的:S004 的「面具上的骨纹走向和犄角棱纹清晰可见」被纯子串匹配误报过。

## 目录与重跑规则（硬性要求）

> **成片只保留一个文件夹 `成片/`,不允许出现 demo2、demo3 这种递增目录。**

### 重跑规则

1. **默认在 `成片/` 里就地覆盖**。重跑某个镜头时,新文件直接写回 `成片/<镜头号>.mp4`,覆盖旧的。
2. **只重跑需要重跑的镜头**,已经验收通过的镜头原样保留,不要连带重生成。
3. **确实需要保留旧版做对比时**,才临时复制一份到 `对比/`,对比完成后立刻删除。
4. **旧的配置目录同理**:提示词配置只保留当前生效的那一份（当前是 `shots_ref5/`）,历史版本用完即删。
5. **删除一律走 `mavis-trash`(回收站),不用 `rm`**,误删可恢复。

### 重跑一个镜头的完整流程（以 S014 为例）

目录结构见本文开头,这里只列步骤。

1. 改生成器:`shots_p1.py` 的 pic / `cast_ep01.py` 的动作表 / `gen_keyframe.py` 的取景段与参考图装配
2. `python3 gen.py` → 母数据与分镜总表更新（**会清掉时间码和人物段**）
3. `python3 gen_keyframe.py` → 关键帧计划。**diff `kf_plan.json`,确认只有目标镜头变化**
4. `python3 sub_keyframe.py S014`（每批 ≤2 张）→ `python3 dl_kf_one.py S014`
5. 抽帧验收关键帧:用 `./zoom` 放大看,**不要只扫缩略图** —— 缩略图上看不清指针,也看不出正侧面那两段珐琅弧边
6. `python3 gen_ep01_video.py` → 视频 prompt。**diff 确认变化范围**,别让 21 条一起漂
7. `python3 batch_video.py S014` → 归档旧片 → 提交 → 轮询 → 下载
8. 重拼成片:`./build_ep01` → `./transcode` → 覆盖 `成片/EP01_说谎者.mp4`
9. `bash refresh_ep01_md.sh` → 刷新时间码与人物段
10. 全片验收:`./vidprobe` 规格 + `./luma` 黑帧 + `/tmp/aud` 音轨 + 字幕落点核对

> **第 3 步和第 6 步的 diff 不能省。** 改一处共用常量（座钟规格、朝向规则、参考图装配顺序）会静默改动全部 21 条 prompt。上一轮就因为补丁插在了 `SHOT_FIX` 直接赋值之前,座钟 12 点约束被整条覆盖掉。

## 模型规格与成本提醒

MiniMax-H3 与 MiniMax-H3-Max 都是**计费**模型。本项目只用 **MiniMax-H3**。

| 项 | MiniMax-H3 |
|---|---|
| 时长 | 4-15 秒 |
| 分辨率 | 768P / 2K |
| 提示词上限 | 7000 字（实测最长 474 字,余量充足） |
| 参考图 | `reference_images`,**上限 9 张** |
| 音轨 | 自带原生同步音频（台词 + 环境音 + 音效 + 配乐） |
| 首帧模式 | `reference_type: "first_frame"`,此时 `ratio` 自动 adaptive,**不能指定** |
| 并发 | 上限 5 条未确认的视频任务 |

> **不要用 H3-Max 跑本项目。** H3-Max 不支持多模态参考,而整条链路（场景底板 + 11 个角色三视图 + 座钟三面 + 山羊头骨）全部依赖参考图。早期文档里「先用 H3-Max 跑通第一集验证风格」的建议是错的 —— 它跑出来的图没法用作参考图驱动的关键帧。

**额度 / 402 / 429 / 账号类错误立即停手原样回报**,不换模型、不降规格。网络 socket 错误可以重试。
